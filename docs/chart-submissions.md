# 歌詞データの投稿と登録

## 投稿者の操作

エディターで歌詞データを作成し、インポート・エクスポートと並ぶ「投稿する」を押す。ログインは不要。投稿画面では、曲名、アーティスト、YouTube URL、投稿者名、補足情報を入力する。必須・任意はラベルで区別する。

曲名・YouTube URL・投稿者名は必須。補足情報は任意で200文字まで。難易度の入力欄は設けず、申請時の難易度は新曲・修正申請とも `-` で初期設定する。想定難易度は補足情報に書ける。管理者が登録前に正式な難易度を設定する。

投稿した曲情報・補足情報・歌詞データはDiscordでゲーム参加者全員に共有される。ランキングへの登録とゲームへの反映は管理者が確認してから行う。投稿画面の開閉やプレイ画面への切り替えでは入力を保持する。

投稿後は編集用リンクをコピーできる。編集キーは同じブラウザのlocalStorageにも保存し、投稿URLには申請IDを付ける。同じブラウザなら履歴の投稿URLから再開できる。別端末ではキーを含む編集用リンクが必要。URL以外から申請を開く専用画面はなく、下書き一覧も編集キーとは連動しない。ブラウザの保存データと編集用リンクを両方失うと復旧できない。編集用リンクを知る人は申請を編集できるため、参加者向けのDiscord通知には載せない。

申請内容を読み込んで変更・再申請できる。登録処理中は変更できず、登録完了・削除後は編集用リンクが無効になる。公開曲は曲一覧または練習画面の「修正申請する」から誰でも新しい申請を作れる。曲番号・曲情報・TXTを引き継ぐ。補足情報は修正申請ごとに入力する。投稿者名は修正を申請する本人が入力する。

## 管理者の操作

`/admin/submissions/` で管理用キーを入力し、申請一覧を読み込む。初期表示は承認待ち。状態・曲番号・曲名・アーティストで絞り込み、20件ずつ表示する。表には曲番号・曲名・アーティスト・難易度・投稿者名・状態・操作を表示する。公開曲は通常の `/songs/` で確認する。

- 「確認・編集」で補足情報、TXT、ダウンロード、プレイプレビューを確認する。
- 曲名・アーティスト・曲番号・難易度は同じ画面で順不同に編集できる。「変更を保存」はLDCの `chart_submission` の各列を直接更新する。曲番号未定でも保存できる。
- 曲番号入力時にランキングとLDCの公開曲を照会する。既存曲の情報を表示し、更新には「この既存曲を更新する」の確認が必要。照会失敗時は登録できない。
- 他の申請と同じ曲番号がある場合は、却下済みや別ページの申請も含めて警告する。重複を許す仕様なので、警告だけで登録を禁止しない。別申請がその番号で登録処理中の場合は、先にその処理を完了する。
- 表の「ランキングに登録」は、確認ポップアップに表示した保存済みの曲情報で登録する。編集画面内の「ランキングに登録」は、編集中の情報を保存してから登録する。
- 不要な申請は却下でき、状態フィルターから確認・承認待ちへの復帰ができる。表の「削除」は確認ポップアップの後に申請を完全削除する。登録処理中の申請は削除できない。

管理キーは画面のメモリだけに保持する。プレビューは歌詞ページを確認する機能で、ポップ演出はTXTまたはゲーム側で確認する。

## 登録と保存データ

ランキングの既存 `PUT /api/v1/admin/songs/{gameSongId}` が成功したら、LDCの `song` を追加・更新し、同じトランザクションで申請を削除する。公開曲には曲情報・YouTube URL・TXTと初回登録時の投稿者名を保存する。修正申請では同じ番号の公開曲を更新し、投稿者名は変更しない。以前から投稿者名が未登録の曲も、修正者の名前で補完しない。補足情報は申請とDiscord通知だけで扱い、公開曲には保存しない。申請が登録・削除されるとDBの補足情報も削除される。

ゲームへのファイル組み込みや配信は自動化しない。ランキング登録・LDC公開の完了後に別途行う。

公開曲の主キーは文字列の `gameSongId`。曲番号は3〜8桁で `000` を除き、先頭ゼロを保持する。申請にも同じ曲番号を保存できるが、公開曲への外部キーや一意制約は設けない。新曲にはまだ公開曲がなく、同じ曲への複数申請も保持するためである。別番号への登録は元の公開曲や成績の番号変更・削除を行わない。

歌詞データの保存先は必須の `Song.scoreTxt` に統一する。練習画面でTXTを解析してページと総時間を取得し、編集用APIは保存したTXTをそのまま返す。取り込みAPI・CLI・GASはゲーム曲番号とTXTで追加・更新し、難易度更新もゲーム曲番号を使う。曲一覧の番号表示・検索・数値順ソート・URLも同じ番号を使う。

### 登録処理の整合性

申請の版番号で同時編集を検出する。変更の保存・却下・復帰後は版番号が変わり、古い画面からの更新・登録・削除は拒否する。

最初の登録操作で曲情報を申請の各列に保存し、状態を `publishing` にして編集を禁止する。曲番号と申請のDBロックをランキング送信から公開保存・申請削除まで保持する。失敗・結果不明の場合は同じ内容で再試行する。その曲の別申請の登録も先に進めない。

LDCとランキングのDBをまたぐ単一トランザクションはないため、ランキング登録が一時的に先行する場合がある。相手側でタイムアウト後も処理が継続する可能性は残る。別システムからの同時登録に対する番号予約は行わない。

## 投稿の制限

Turnstileをサーバーで検証し、成功・hostname・actionを確認する。未設定・検証失敗時は投稿を受け付けない。アプリはIPアドレスを取得・保存・ハッシュ化せず、Turnstileにも転送しない。日次の投稿回数制限は設けない。

保存する申請は `SUBMISSION_TOTAL_LIMIT` の初期値50件まで。承認待ち・登録処理中・却下済みを合算し、公開曲は含めない。上限到達時は新規投稿だけを停止し、既存申請の編集・登録は続けられる。新規作成の件数確認はDBロックで直列化する。同じ投稿の再試行では申請を増やさない。登録完了または管理者の削除で枠が空く。

本文は160KiB、TXTは128KiB、歌詞ページとポップは各1000件、総時間は3600秒まで。YouTube URLはHTTPSの動画URLに限定し、正規URLへ変換する。入力された任意のURLをサーバーから取得しない。SQLは値をパラメーターとして渡し、画面上の投稿内容はテキストとして表示する。

### 入力の文字数上限

| 項目 | 投稿APIの上限 |
|---|---|
| 曲名 | 100文字 |
| アーティスト | 100文字 |
| 投稿者名 | 20文字 |
| 補足情報 | 200文字 |
| YouTube URL | 100文字。保存時は正規URLへ変換 |
| 曲番号 | 3〜8桁の数字 |
| 難易度 | 管理者入力は最大4文字。1〜99と任意の+/-、または-/?の形式を検証 |
| TXT | UTF-8で128KiB |

DBの文字列列はTEXTで、文字数上限は投稿・管理APIで検証する。入力画面にもmaxLengthを設定する。サーバーはUnicodeコードポイント数、ブラウザのmaxLengthはUTF-16の長さで数えるため、絵文字などでは入力画面の上限が先に来る場合がある。取り込みAPIでも曲名・アーティスト・YouTube URLに同じ上限を適用する。SQL・復元ツールなどでDBへ直接書き込む場合はAPIの検証を通らない。既存の保存データは自動で切り詰めない。

## Discord通知

任意の `DISCORD_SUBMISSION_WEBHOOK_URL` をサーバー環境変数に設定する。未設定では投稿保存だけを行う。通常のチャンネルまたは既存スレッドのIncoming Webhookに対応し、フォーラムへの新規スレッド作成は行わない。

新規申請・再申請の保存後に、曲名 → アーティスト → YouTube URL → 補足情報 → 投稿者名の順で通知する。補足情報がなければ省略する。補足情報は1つの項目として送り、分割しない。現在の入力上限はDiscordの1項目1024文字・埋め込み全体6000文字の範囲に収まる。未入力のアーティストは「未入力」と表示する。歌詞データTXTを `chart.txt` として添付する。添付ファイルと埋め込みの表示位置はDiscord側の表示に従う。

管理画面URL・内部の申請ID・版番号・編集キー・管理キーは送信しない。メンションを無効化し、最大5秒で送信結果を確認する。失敗しても申請保存は成功し、投稿画面に案内を出す。同一内容のAPI再試行では通知を重複させない。管理画面からの再送機能や自動再送キューは設けない。Discordに送信済みのメッセージや添付は、申請を削除しても残る。

## 導入

1. DBをバックアップし、既存曲の `gameSongId` が正しいゲーム曲番号で全件設定済みか確認する。旧内部IDから番号を推測しない。
2. `npm ci`、`npx prisma migrate deploy`、`npx prisma generate` を実行する。追加マイグレーションは `20261029000000_chart_submissions` の1つ。
3. 必要な環境変数を設定してビルド・起動する。

マイグレーションは旧 `song.id` を削除して主キーを `gameSongId` に変更する。不正・未設定・重複番号があればトランザクション全体を戻す。TXT未保存の曲は旧ページ配列からTXTへ変換し、保存済みTXTは保持する。旧データにないポップや元の総時間は復元できないため、総時間は最終ページ＋5秒、空配列なら5秒とする。構造不正なページがあれば列削除も含めてロールバックする。

| 環境変数 | 用途 |
|---|---|
| `DATABASE_URL` | PostgreSQL接続先 |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | 公開サイトキー。ビルド時にも必要 |
| `TURNSTILE_SECRET_KEY` | Turnstile秘密キー |
| `TURNSTILE_HOSTNAME` | 許可するホスト名。スキーム・パスなし |
| `SUBMISSION_ADMIN_KEY` | LDC管理用の32文字以上のランダムな秘密キー |
| `RANKING_ADMIN_API_KEY` | ランキング側の既存管理用キー |
| `SUBMISSION_TOTAL_LIMIT` | 保存申請数の上限。初期値50 |
| `DISCORD_SUBMISSION_WEBHOOK_URL` | 任意の参加者向け通知先 |

ランキング側のコード・DB・CORS変更は不要。登録APIには曲名・アーティスト・難易度だけを送り、曲番号はURLで指定する。番号確認には既存公開API `GET /api/v1/songs/{gameSongId}/rankings?players=1&limit=1` を使い、404だけを未登録と扱う。

## ローカル確認

Prismaと移行コマンドは `.env` の `DATABASE_URL` を使う。Next.jsの `.env.local` も同じ開発DBを指定する。投稿確認にはCloudflare公式の成功用テストキーを使える。

```dotenv
NEXT_PUBLIC_TURNSTILE_SITE_KEY=1x00000000000000000000AA
TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA
TURNSTILE_HOSTNAME=localhost
SUBMISSION_ADMIN_KEY=32文字以上のランダム文字列
SUBMISSION_TOTAL_LIMIT=50
RANKING_ADMIN_API_KEY=
DISCORD_SUBMISSION_WEBHOOK_URL=
```

```sh
npm run dev
```

`http://localhost:3000/editor/` から投稿し、`http://localhost:3000/admin/submissions/` で確認する。環境変数の変更後は開発サーバーを再起動する。

テストキーのhostname/actionの例外は開発モードと正確な公式成功用キー・ダミートークンの組合せだけで有効。Siteverifyへの通信と成功判定は省略しない。

ランキング登録の接続先は本番の `ranking.kayomodoki.com`。ローカルの投稿・編集・却下・削除確認ではランキング管理キーを空欄にし、実際の登録は行わない。Discordも確認する場合はテスト用チャンネルのWebhookを使う。

## 管理API

管理者認証は `Authorization: Bearer <SUBMISSION_ADMIN_KEY>`。

- `GET /api/admin/submissions/?page=1&status=pending&q=曲名`：申請表と同番号の申請数。
- `GET /api/admin/submissions/{id}/`：申請全文と版番号。
- `POST /api/admin/submissions/{id}/`：`save`・`approve`・`reject`・`restore`。版番号を必須とし、保存・登録には `registration` で曲番号・曲名・アーティスト・難易度を指定する。既存曲の更新時は `allowOverwrite:true` が必要。
- `DELETE /api/admin/submissions/{id}/`：本文に `{"revision":1}` を指定して申請を削除。
- `GET /api/admin/ranking-song/?gameSongId=001&submissionId=申請ID`：ランキング・公開曲・自分以外の同番号申請を確認。

管理キー・編集キー・投稿全文をアクセスログやエラー調査ログへ保存しない。
